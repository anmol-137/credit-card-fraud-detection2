    What to keep in mind

    • Fraud is about 0.17% of transactions, so accuracy is meaningless here. Judge the model on precision, recall and PR-AUC.
    • The fraud score is a model score, not a calibrated probability. The cut-off was chosen on a validation set to balance precision and recall.
    • The test set holds only a few dozen fraud cases, so the numbers carry real uncertainty.
    • The data is two days of European card transactions from 2013. This is a learning project, not a system to make real payment decisions.

    Use it from your own code

    Everything on this page calls the same JSON API. Interactive docs are at /docs.

    • GET /api/model returns the model card
    • POST /api/predict scores one transaction
    • POST /api/predict/batch scores a CSV upload
    • GET /api/health reports status
